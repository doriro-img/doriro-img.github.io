이 문서는 자화자찬용이 아닙니다. 약점을 찾아달라고 쓴 것입니다.
아래 6장에 우리가 아는 결함을 먼저 적어뒀습니다. 우리가 모르는 결함을 찾아주세요.

───────────────────────────────────────────────────────────────────────────────
1. 무엇을 하는 시스템인가
───────────────────────────────────────────────────────────────────────────────

한 사람이 운영하는 한국어 정보 블로그(티스토리)의 원고를 LLM 세션이 대량 생산합니다.
수익 모델은 구글 애드센스입니다.

  대상 주제   정부 정책·지원금 / 금융·생활 경제 / 생활 규정·IT
  생산 속도   하루 3편 × 한 달 = 월 90편 안팎
  현재 규모   원고 182편 (신형식 116편 + 옛형식 66편)
  발행        LLM 은 원고만 만들고, 티스토리 붙여넣기는 사람이 손으로 함

핵심 구조는 **LLM 이 판단하고 스크립트가 검사한다** 입니다.
LLM 한 세션이 프롬프트를 받아 라인업 확정부터 90편 완성까지 한 턴으로 달립니다.
매 2편마다 검사 스크립트가 돌고, 걸리면 그 자리에서 고치고 다음으로 갑니다.
사람에게 물어보지 않습니다 — 멈추면 턴이 끊기고 자동화가 깨지기 때문입니다.

4. 실측 데이터 — 이 시스템이 "감" 대신 쓰는 것
───────────────────────────────────────────────────────────────────────────────

네이버 검색광고 API 로 실제 월간 검색량과 광고 클릭 성향을 잽니다.
아래는 전부 2026-08-23 실측치입니다.

【검색량과 광고 CTR 은 별개다】

  자동차보험   117,200 검색   광고 CTR 5.77%   광고 10개
  신용점수      21,970 검색   광고 CTR 2.55%   광고 10개
  실업급여     111,500 검색   광고 CTR 0.22%   광고  7개
  태풍       7,677,600 검색   광고 CTR 0.01%   광고  1개
  국가장학금   138,800 검색   광고 CTR 0.00%   광고  0개

  → 국가장학금은 13.9만 명이 찾는데 광고 클릭이 0이다.
    행정·제도 키워드는 본질적으로 광고가 안 붙는다. 이 블로그의 주력이 그렇다.

【기존 원고 87편을 유입 × 수익 두 축으로 가른 결과】

  유입 O · 수익 O    37편
  유입 O · 수익 X    48편   ← 사람은 오는데 광고를 안 누른다
  유입 X · 수익 O     0편
  유입 X · 수익 X     2편   ← 실제로는 1편 (1편은 씨앗이 틀린 것)

  → 87편 중 새로 써야 할 건 1편이었다.

【씨앗이 영토를 완전히 결정한다】

  서로 다른 씨앗으로 각각 4라운드 크롤한 결과의 겹침(자카드)

    지원금 ∩ 과태료   12.9%
    지원금 ∩ 연금      1.8%
    과태료 ∩ 연금      5.8%
    각 크롤의 71~87% 가 자기만의 영역

  → 수렴하지 않는다. 그래서 씨앗 목록을 사람이 정하면 그 목록 밖은 영영 못 본다.
    지금은 이미 쓴 원고 주제에서 씨앗을 자동 추출한다 (95개).

【연도 접두 수요는 주제마다 갈린다】

  자녀장려금   →  "2026 자녀장려금"  100,190회   연 1회 신청 제도
  국민연금     →  "2026 국민연금"        100회   상시 제도
  연말정산     →  "2026 연말정산"        210회
  건강보험료   →  "2026 건강보험료"       60회

  → 전자는 매년 새 글이 정당하고, 후자는 기존 글 수정이 맞다.
    "정책이 바뀌었나" 는 기계가 못 보지만 이건 잴 수 있다.


───────────────────────────────────────────────────────────────────────────────
5. 이 시스템이 스스로 고친 것 — 설계 이력
───────────────────────────────────────────────────────────────────────────────

측정해서 틀린 걸 찾아낸 사례입니다. 판단 근거로 참고하세요.

【소제목이 검색어에서 주어를 빼먹고 있었다】

  검색어    "하이패스 미납요금 조회" (4,270회)
  소제목    "미납요금 조회는 어디서 하나요?"   ← 주어 없음

  검사기가 "씨앗을 빼고 꼬리말만" 비교하도록 설계돼 있어서 통과했다.
  실측: 상위 롱테일 81개 중 원형으로 담긴 건 4개(5%)뿐이었다.
  → 검사를 원형 대조로 바꿈. 8월은 손으로 47줄 교정(5%→57%),
    9월은 세션이 새 검사 규칙을 받아 스스로 57편을 고쳤다.

【탐지 회피용 규칙이 탐지 신호를 만들고 있었다】

  검사기가 편당 하한을 4개 걸고 있었다 — 더라고요 2회 이상, 혼잣말 필수,
  1인칭 필수, 말줄임표 필수. 그 결과 103편 전부가 넷을 다 갖췄다.

    더라고요 평균 4.6 · 변동계수 0.33 · 0회인 편 0/103
    1인칭 100% · 혼잣말 100% · 말줄임표 100%

  사람이 103편을 쓰면 어떤 글엔 아예 안 나온다. 이 균일성 자체가 지문이다.
  → 하한을 없애고 묶음 분산 검사로 바꿈. 프롬프트도 "한 달치 분포" 로 교체.

【씨앗이 좁으면 대표층을 통째로 놓친다】

  씨앗 "태풍 대비 행동요령" → 수집 후보 최대 10회
  그런데 "태풍" 단독은 7,677,600회였다.
  자동완성은 씨앗의 가지만 보여주므로 더 큰 말이 후보에 아예 안 들어온다.
  → 씨앗을 쪼갠 조각도 같이 재서 "대표층 누락" 을 경고하게 함.

【검색량 1위가 정답이 아니다】

  장애인 활동지원사   39,950회   ← 활동지원사가 되려는 구직자
  장애인 활동지원     19,680회   ← 서비스를 받으려는 수급자

  원고가 수급자용인데 검색량 1위를 그대로 쓰면 대상이 어긋난다.
  → 의도 판정은 기계가 못 하므로 규칙으로 명시하고 LLM 판단에 맡김.

【화자 정체성 모순 1건】

  화자는 실제 인물이다 — 기혼 남성, 아내 있음, 자녀 없음, 김포 거주.
  107편 전수 검사에서 "저희도 연휴에 아이가 아파서" 1건을 찾아 고쳤다.
  → 화자 설정을 코드에 박고 모순 표현을 반려 항목으로 만듦.
    (반대로 "아내 15편·김포 6편" 반복은 오염이 아니라 일관성이다.
     김포 6편이 전부 다른 사건이었다 — 더위·태풍·층간소음·대출·처가·출근)

【연도 하드코딩】

  audit.cjs 가 PNG 경로를 이렇게 만들고 있었다.
    path.join(ROOT, '2026', String(new Date().getMonth() + 1))
  연도가 고정이고, 월을 인자가 아니라 오늘 날짜에서 가져왔다.
  8월에 9월 원고를 검사하면 2026/08 을 뒤졌다. 2027년엔 통째로 깨진다.
  → 연·월 경로를 공용 모듈로 빼고 프롬프트의 2026 하드코딩 38곳을 변수화.


───────────────────────────────────────────────────────────────────────────────
6. 우리가 아는 약점 — 여기부터가 본론입니다
───────────────────────────────────────────────────────────────────────────────

【A. 경쟁률을 아예 못 잰다 — 가장 큰 구멍】

  검색량은 실측하지만 "그 검색어로 순위를 잡을 수 있는가" 는 모릅니다.
  네이버 오픈API(문서수)를 쓰면 잴 수 있는데 안 쓰기로 했습니다.

  그래서 "유입 가능성 있음" 은 "검색량이 0은 아니다" 이상의 뜻이 없습니다.
  확실한 건 반대 방향뿐입니다 — 검색량이 0이면 순위와 무관하게 유입 0.

  검색광고의 compIdx 는 광고주 경쟁률이지 SEO 경쟁률이 아닙니다.
  (태풍 767만 검색인데 광고가 1개 붙습니다. 그렇다고 블로그가 1등 하지 않습니다)

【B. 검색광고 API 가 일부 키워드를 가린다】

  기초연금 15회 · 자녀장려금 10회로 나옵니다. 근로장려금은 342,100 으로 정상입니다.
  원인을 확정하지 못했습니다. 정부 복지 키워드 일부가 광고 제한에 걸리는 것으로 보입니다.
  그래서 "< 10" 을 저수요로 단정하면 멀쩡한 주제를 버리게 됩니다.

【C. 문체 균일성이 아직 남아 있다】

  규칙은 고쳤지만 이미 쓴 원고는 균일한 채입니다.

    8월 27편   더라고요 변동계수 0.31 · 1인칭 100% · 혼잣말 100% · 말줄임표 100%
    9월 89편   변동계수 0.39 · 0회 7편 · 1인칭 97% · 혼잣말 93%   ← 개선 중

  9월이 나아지고 있지만 여전히 사람의 분포(0.6~1.0)와 거리가 있습니다.

【D. 1인칭 경험의 진위】

  "저희 김포 집도 재작년에 그랬습니다" 같은 문장이 편당 2.3개 들어갑니다.
  화자 설정은 실제 인물과 맞추지만, 개별 에피소드가 실제 경험인지는
  시스템이 보증하지 못합니다. LLM 이 그럴듯하게 지어낼 수 있습니다.

【E. 성과 데이터가 하나도 없다】

  GA4·애드센스 실적을 파이프라인이 안 봅니다. 위의 모든 지표는 사전 지표입니다.
  "이 구조가 실제로 유입과 수익을 냈는가" 를 증명하는 데이터가 없습니다.
  발행 이력도 짧습니다 (8월 27편이 오늘부터 발행 시작).

【F. 발행이 수동이다】

  원고와 썸네일까지 자동이고 티스토리 업로드는 손으로 합니다.
  발행 보드(HTML)로 복사 버튼을 만들어뒀지만 클릭은 사람이 합니다.

【G. 중복 판정이 부분 문자열 기반이라 약하다】

  "국민내일배움카드" 와 "내일배움카드신청" 을 서로 다른 주제로 봅니다.
  둘 다 후보로 올라올 수 있습니다.

【H. 미끼 트래픽 전략의 실행이 미완】

  유입은 크지만 광고가 안 붙는 글이 48편입니다(태풍 CTR 0.01%, 국가장학금 0%).
  이런 글은 광고를 줄이고 수익 글로 내부 링크를 보내는 게 맞다고 판단했지만
  레이아웃 분리를 아직 구현하지 않았습니다. 지금은 전부 같은 템플릿입니다.

【I. 인라인 CSS 도식의 무게】

  본문 HTML 14.6KB 중 텍스트가 7.6KB(52%)입니다. 나머지는 카드 4장의 인라인 CSS 입니다.
  가독성과 스니펫 확보를 노린 설계인데, 이게 오히려 불리한지 검증하지 못했습니다.

【J. 무효 클릭 방어가 없다】

  애드센스 무효 클릭 차단 코드가 레포에 없습니다.
  (예전에 있다고 알고 있었는데 실제로 확인하니 없었습니다)
